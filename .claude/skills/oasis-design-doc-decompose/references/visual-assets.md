# 视觉素材读取（画板 / 截图 / 表格）

腾讯文档需求文档里，**决定实现细节的信息常常不在文字里**——画板画着界面结构，截图定着状态和文案，表格装着数值和枚举。只读文字就出功能点清单，等于默认这些不存在。

**铁律：功能点清单必须覆盖视觉素材，不只是文字段落。**

---

## 1. 分类处理

| 素材 | 提取什么 | 落到哪 |
| --- | --- | --- |
| **画板 / 白板** | 界面元素清单、层级、箭头标注的交互 | `01` 功能点；结构性的进 `03-plan` 界面结构 |
| **UI 截图 / 原型图** | 控件、状态、文案、空态与错误态 | 功能点 + 后续验收基准 |
| **参考 / 竞品截图** | 只有被标注「照着做」的部分算需求，其余忽略 | `03-plan` 参照物 |
| **表格** | 数值、状态枚举、解锁条件 → **DataTable/DA/配置字段的天然来源** | `03-plan` 配置决策 |
| **流程图 / 时序图** | 状态机、调用序列、分支条件、客户端/服务端分工 | `03-plan` 逻辑层与网络层任务 |
| 纯装饰配图 | 无 | 忽略 |

**表格值得单独强调**：策划画的表格基本就是 DataTable/DA 的雏形，字段名和枚举值都在里面，比读文字猜快得多，也准得多。

## 2. 怎么「看到」

- **优先复制取内容，不截图。** 用 `scripts/read_tencent_doc.py` 全选复制到系统临时目录：文字进 `document.md` / `document.txt`，图片从复制 HTML 的 data URI 提取到 `images/`，表格转 Markdown。文字读文本，图片读原图；临时目录不放进 `spec/`
- **复制不可用时才截图。** `--mode screenshot` 输出 `page-NNN.png`，按滚动位置分段、相邻有重叠；只在复制被禁用、剪贴板为空或需要排版基准时使用
- **腾讯文档图片走鉴权 CDN**，直接 curl 拿不到；用脚本的浏览器上下文复制/提取，不靠匿名请求
- 长文档分段截；**虚拟滚动会漏内容**，截完自查连贯性（前后屏要有重叠）
- 表格优先局部放大截。分辨率不够时关键数值回原文二次确认——**数字看错比没看到更糟**
- 画板可能超出视口：缩放 / 平移后分块截

**先确认文档完整加载**：页面出现「登录腾讯文档」「只能查看」「正在同步内容...」时，正文可能只到一部分。此时：

1. 优先用已登录浏览器重读；
2. 无法登录时，请用户导出（Word/PDF）或粘贴全文；
3. 仍拿不到就明确标注「本轮只读到部分内容」，**不得把缺失当成文档没有**。

**能力缺失必须报告**：拿不到视觉能力或截图失败时，在 `01-understand.md` 写明「本轮未读取视觉素材，功能点仅基于文字」，并列出哪些素材没读到。**禁止假装读过。**

## 3. 视觉指纹：变更检测的真实漏洞

`06-sync.md` 的哈希基于文字。**图改了、文字没改，检测不到**——而画板恰恰是策划最常改的东西。

补偿：FP 行加**素材来源**列，记来源 + 关键视觉描述（元素数量 / 关键文案 / 布局要点）。同步比对时描述变了即变更；拿不准就在报告里提示人确认视觉部分。

## 4. 落盘：只存关键的

存到 `spec/<模块名>/assets/`，命名 `fp-xxx-<简述>.png`。

读取脚本的原始图片先落系统临时目录的 `images/`；进入 Phase A 后只把影响功能点的复制/重命名为 `spec/<模块名>/assets/fp-xxx-<简述>.png`，其余临时文件在 Phase A 结束后删除。

只存**影响功能点的**——它是界面验收基准，也是下次判断「画板改没改」的基线。装饰性配图不存。

## 5. 易踩的坑

- **只读文字就拆** → 功能点整块缺失，且缺失是静默的
- **未登录/未加载完就拆** → 把「没读到」当成「文档没写」
- **声称读图实际没读** → 必须报告，不准含糊过去
- **截图漏内容**（虚拟滚动、长图截断）
- **表格数字看错** → 关键数值二次确认
- **把参考截图全当需求** → 只有标注「照着做」的算
- **画板改了文字没改** → 视觉指纹（§3）
